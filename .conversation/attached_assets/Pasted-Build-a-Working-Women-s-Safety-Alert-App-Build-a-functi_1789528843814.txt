Build a Working Women’s Safety Alert App
 
Build a functional, mobile-friendly Women’s Safety Alert app called SafeHer. This is a working app, not a portfolio website or project report. Do not create AON/AOE diagrams, CPM/PERT charts, Gantt charts, or academic documentation.
 
Important instructions
 
- Build the complete app in the current Replit project.
- Keep the implementation simple and beginner-friendly.
- Use the existing project setup if one is already present. Avoid unnecessary dependencies and extra files.
- Do not repeatedly ask me questions. Make sensible choices and explain any required setup.
- Prioritize working features over decorative extras.
- Do not add features that are not listed below.
 
Design
 
- Use a clean, modern interface with soft lavender, white, and light pink.
- Use readable typography, rounded cards, clear icons, and accessible button sizes.
- Make it responsive, especially for mobile screens.
- Add a bottom navigation bar with Home, Safety, Contacts, and Profile.
- Keep the interface simple and easy to use in an emergency.
 
Required working features
 
1. Home screen
 
- Show the app name and a clear SOS button.
- Show the current location status: “Location available” or “Location unavailable.”
- Include shortcuts to Safety, Contacts, and Incident Report.
- Add a clearly labeled Demo Mode indicator.
 
2. SOS alert
 
- When the SOS button is pressed, show a confirmation screen before proceeding.
- Request location permission only when needed.
- If permission is granted, retrieve the current location and display it.
- Prepare an emergency message containing the location and a map link, if available.
- Show the selected emergency contacts and the message before any real alert is sent.
- Do not send SMS, make calls, or contact emergency services automatically. Real messaging must remain disabled unless a supported service is configured and the user explicitly confirms.
- In Demo Mode, simulate the alert and show a clear success message such as “Demo alert created — no message was sent.”
- Handle denied location permission or unavailable location with a clear explanation and manual fallback.
 
3. Emergency contacts
 
- Let the user add, edit, and delete contacts.
- Store contact details locally or in the project’s existing database.
- Validate required fields and phone-number input.
- Let the user select which contacts should receive an alert.
- Do not send messages merely because a contact is saved.
 
4. Location screen
 
- Add a button to get the current location.
- Display latitude and longitude.
- If a map service is configured, show the location on a map.
- Provide a map link that the user can open or copy.
- Do not track the user continuously in the background.
 
5. Safety tools
 
- Add a Siren button with Start and Stop controls. Audio must begin only after the user presses Start.
- Add a Fake Call Demo that displays a simulated incoming call screen. It must not place a real call.
- Add an Incident Report form with incident type, date/time, location (optional), and notes. Save reports locally or in the existing database.
 
6. Profile and settings
 
- Allow the user to enter or edit their name.
- Include settings for Demo Mode and location access.
- Clearly explain what each permission is used for.
 
Technical requirements
 
- Use the simplest suitable stack already available in the Replit project.
- Make every visible button and form functional.
- Save contacts, profile details, and incident reports so they remain after refreshing the app.
- Use environment variables for any API keys. Never expose secret keys in frontend code.
- If a map or external service requires an API key, provide a clear setup note and keep the rest of the app usable without it.
- Include loading, success, empty, and error states where appropriate.
- Do not display fake GPS coordinates or claim that a real alert was sent.
- Add a short README with how to run the app and configure any optional services.
 
Build order
 
1. First make the app run.
2. Implement navigation and the Home screen.
3. Implement contacts and saved data.
4. Implement location and the Demo SOS flow.
5. Implement the siren, fake-call demo, and incident report.
6. Test the main user flows and fix errors.
 
Deliver the working app, not just a plan, mockup, or explanation. After building, briefly tell me what works and whether any setup is still required.
